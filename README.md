# dominion-grpc

A server-authoritative Dominion implementation in Go. Uses Connect-Go over
HTTP/2 for the RPC layer; protobuf is the single source of truth for the
contract between server and any client (bots, future UI, tests).

**Status:** Phase 1a / Tier 0 complete — basics (Copper/Silver/Gold,
Estate/Duchy/Province/Curse) + BigMoney strategy play end-to-end via a
bot-vs-bot integration test. See the design spec in the dev-env repo under
`docs/dominion/` for architecture decisions and the road-map.

## Quick start

```bash
# In one terminal — start the server
make server

# In another terminal — run two BigMoney bots against each other
make bot ARGS="--server http://localhost:8080 --player alice"
make bot ARGS="--server http://localhost:8080 --player bob"
```

## Make targets

| Target | Description |
|---|---|
| `make generate` | Regenerate `gen/go/` from `proto/` via buf |
| `make test` | Full test suite (including 500-seed property sweep) |
| `make test-short` | Skip the long property and integration sweeps |
| `make lint` | buf lint + golangci-lint |
| `make server` | Run Connect-Go server on `:8080` |
| `make bot ARGS=…` | Run standalone bot CLI with extra args |
| `make tidy` | `go mod tidy` |
| `make install-tools` | Install buf and golangci-lint into `$GOPATH/bin` |

## Playing a bot-vs-bot game manually

1. `make server` — server listens on `http://localhost:8080`
2. Create a game (curl example):

```bash
curl -s -X POST http://localhost:8080/dominion.v1.GameService/CreateGame \
  -H 'Content-Type: application/json' \
  -d '{"players":["alice","bob"],"seed":42}'
```

3. Stream events for player 0:

```bash
curl -s -X POST http://localhost:8080/dominion.v1.GameService/StreamGameEvents \
  -H 'Content-Type: application/json' \
  -d '{"game_id":"<id>","player_idx":0}'
```

4. Submit an action:

```bash
curl -s -X POST http://localhost:8080/dominion.v1.GameService/SubmitAction \
  -H 'Content-Type: application/json' \
  -d '{"game_id":"<id>","action":{"end_phase":{"player_idx":0}}}'
```

## Layout

```
proto/                    source of truth — protobuf contract
gen/go/                   generated Go stubs (committed; never hand-edit)
cmd/server/               Connect-Go HTTP/2 server entry point
cmd/bot/                  bot CLI entry point
internal/engine/          pure Go game engine (no network, no protobuf)
  cards/                  card definitions (basics registered via init())
  testdata/replays/       JSON replay fixtures for regression tests
internal/service/         Connect handlers — proto ↔ engine translation
internal/store/           in-memory game registry (sync.Mutex + map)
internal/bot/             bot library: state reducer, strategies, run loop
docs/superpowers/plans/   implementation plans (generated by Superpowers)
```
